# Software Requirements Specification (SRS)

## 1. Project Overview
* **Name:** Slothbox
* **Tagline:** Save it. Forget it. Find it.
* **Platform:** Telegram (Long Polling via `python-telegram-bot` v20+)
* **Core Principle:** All AI processing runs 100% locally via Ollama. All persistence resides in a single, local SQLite database file (`slothbox.db`). Zero mock data, zero synthetic fallback responses, zero fake implementations. If any component fails (Ollama offline, model unloaded, network down), Slothbox transparently reports the exact error to the user—it never silently substitutes dummy content.
* **Target User:** Single-user personal knowledge vault (you), capturing text, links, documents, and images on mobile/desktop Telegram without transmitting private data to cloud AI services.

## 2. Hard Requirements (Non-Negotiable)
These requirements exist specifically to guarantee local privacy, system integrity, and prevent fake/mock behavior:

| # | Requirement | Rationale |
| :--- | :--- | :--- |
| **HR-1** | **Strict Local AI Processing:** Every saved item must be processed by the active local Ollama model. If Ollama is unreachable or crashes, Slothbox must reply with an explicit error message and persist the item with status `'failed'`. It must never fabricate summaries or tags. | No fake AI processing |
| **HR-2** | **Actual Semantic Embeddings:** Semantic search must use actual vector embeddings generated by the local embedding model via Ollama. If embedding fails, search must return an error—never fall back to SQL `LIKE '%keyword%'` queries. | No fake search |
| **HR-3** | **Long Polling Only:** The Telegram bot must use long polling (`start_polling()`). No webhooks, no public IP or domain, and no tunneling tools (e.g., ngrok/localtunnel). | Zero deployment complexity |
| **HR-4** | **Local File Persistence:** All items, metadata, tags, and binary embedding vectors must persist in a local SQLite database (`slothbox.db`). Raw media files must be stored locally in `./data/media/`. | Full restart resilience |
| **HR-5** | **Local-Only Privacy Boundary:** All data storage, embeddings, LLM inference, and vector searches run 100% locally on localhost. Outbound network communication is strictly restricted to the Telegram Bot API (`api.telegram.org`) for messaging and optional HTTP fetching of user-provided URLs. | Data privacy & air-gap compute |
| **HR-6** | **Single-User Access Authorization:** Slothbox must verify the sender's Telegram User ID against `TELEGRAM_ALLOWED_USER_ID`. Messages from unauthorized users must be rejected immediately to protect private data and prevent unauthorized compute execution. | Security & compute protection |
| **HR-7** | **Zero Synthetic/Sample Data:** No hardcoded sample seeds in code or database migrations. The database initializes completely empty and only records real user captures. | Clean, honest state |

## 4. Functional Requirements

### FR-1: Multi-Format Capture & Immediate Acknowledgment
1. **Inputs Supported:** Plain text, URLs, photos/images, and documents (PDF, TXT, MD).
2. **Immediate Acknowledgment:** Slothbox immediately acknowledges receipt within <2 seconds before AI processing:
   > *"Saved to Slothbox. Processing..."*
3. **Local Ingestion:**
   * Raw text and URLs are recorded directly in `slothbox.db`.
   * Images and documents are downloaded locally into `./data/media/<file_unique_id>.<ext>` and referenced via `file_path`.
   * The item is inserted with `status = 'pending'`.

### FR-2: Asynchronous Background AI Processing
1. **Non-Blocking Execution:** Background processing uses `ollama.AsyncClient` or worker threads so the Telegram bot polling loop remains responsive.
2. **Text / URL Processing:**
   * For URLs: Fetches page content using `httpx` (with timeout and fallback to raw URL if unreachable), extracts text, and passes it to the configured LLM.
   * Generates a **one-line summary** and **3–5 concise tags** (stored as JSON array).
3. **Image Processing:**
   * Passes the local image file to the configured Vision model to produce a concise descriptive summary and relevant tags.
4. **Vector Embedding:**
   * Generates a dense vector embedding for the content (summary + raw text) using `ollama.embed(model=OLLAMA_EMBED_MODEL, input=...)`.
   * Converts the embedding vector to `np.float32` binary bytes and stores it in the `embeddings` table.
5. **Success / Failure State:**
   * On success: Updates item `status = 'processed'` and sends an updated confirmation or silently marks done.
   * On failure: Updates item `status = 'failed'` with `error_message`, and notifies the user:
     > *"Slothbox couldn't process this: Ollama not reachable / model error. Item saved but not processed."*

### FR-3: Semantic Search
1. **Query Input:** User invokes `/search <natural language query>` (e.g., `/search that article about local RAG architecture`).
2. **Query Vectorization:** Calls Ollama embedding endpoint for the query text.
3. **Similarity Computation:** Retrieves stored vectors from `embeddings`, unpacks binary buffers into NumPy arrays, and calculates cosine similarities:
   $$\text{similarity} = \frac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\| \|\mathbf{v}\|}$$
4. **Result Delivery:** Returns top 3 matches ranked by similarity score, formatted with:
   * Summary
   * Tags
   * Original snippet or URL
   * Save date & Item ID
5. **Strict Failure Guard:** If embedding generation fails, responds:
   > *"Slothbox search failed: embedding model unavailable."*
   It strictly forbids falling back to keyword search.

### FR-4: Daily Resurfacing & Stash Triage
1. **Resurfacing Trigger:** Triggered manually via `/digest` or scheduled as a daily job.
2. **Selection Logic:** Queries `items` where `status = 'processed'`, `is_archived = 0`, `opened_at IS NULL`, and `created_at <= datetime('now', '-7 days')`. Orders by random or oldest.
3. **User Action:**
   * Sends the resurfaced item:
     > *"You saved this 12 days ago. Still interested?*\n\n*[Summary]*\n*Tags: #tag1 #tag2*"
   * Provides inline buttons or commands:
     * `/keep <id>`: Updates `opened_at = datetime('now')`, keeping it active.
     * `/archive <id>`: Updates `is_archived = 1` and `archived_at = datetime('now')`.
4. **Empty State:** If no items qualify, replies: *"No items to resurface."*

## 5. Non-Functional Requirements (NFR)

* **NFR-1 (Resource Footprint):** Must run smoothly on standard consumer hardware (8GB+ RAM) with CPU or local GPU inference.
* **NFR-2 (Latency SLA):** Telegram capture acknowledgment within **2 seconds**; heavy LLM inference executes asynchronously.
* **NFR-3 (Single-File Portability):** Entire state lives in `slothbox.db` and `./data/media/`, enabling zero-config backup via simple file copy.
* **NFR-4 (Asynchronous Concurrency):** Long-polling loop must never block on Ollama HTTP calls; use `ollama.AsyncClient` or worker task execution.
* **NFR-5 (Transparent Observability):** Every failure condition must be logged to stdout and surfaced concisely to the user.

## 7. Database Schema (SQLite: `slothbox.db`)

```sql
-- Core Stored Items
CREATE TABLE IF NOT EXISTS items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    raw_content TEXT NOT NULL,                  -- Original URL, raw text, or caption
    content_type TEXT NOT NULL,                 -- 'url' | 'text' | 'image' | 'document'
    file_path TEXT,                             -- Local filesystem path for downloaded media
    summary TEXT,                               -- NULL if processing failed
    tags TEXT,                                  -- JSON array string (e.g., '["ai", "rag"]')
    status TEXT DEFAULT 'pending',              -- 'pending' | 'processed' | 'failed'
    error_message TEXT,                         -- Populated on failure
    is_archived INTEGER DEFAULT 0,              -- 0 = active, 1 = archived
    created_at TEXT DEFAULT (datetime('now')),  -- ISO8601 UTC timestamp
    opened_at TEXT,                             -- ISO8601 UTC timestamp
    archived_at TEXT                            -- ISO8601 UTC timestamp
);

-- Dense Vector Embeddings for Semantic Search
CREATE TABLE IF NOT EXISTS embeddings (
    item_id INTEGER PRIMARY KEY,
    vector BLOB NOT NULL,                       -- 32-bit float array serialized as binary bytes
    dim INTEGER NOT NULL,                       -- Vector dimensions (e.g., 768)
    FOREIGN KEY (item_id) REFERENCES items(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_items_status ON items(status);
CREATE INDEX IF NOT EXISTS idx_items_archived ON items(is_archived);
CREATE INDEX IF NOT EXISTS idx_items_created_at ON items(created_at);
```

## 9. Acceptance Tests (Zero Mock Toleration)

| # | Test Scenario | Execution | Pass Condition | Fail Condition |
| :--- | :--- | :--- | :--- | :--- |
| **T1** | Unauthorized Access | Send message from unlisted Telegram User ID | Bot silently drops message or replies "Access Denied"; no DB record created | Bot processes message |
| **T2** | Text/URL Capture with Ollama Online | Send text or link with Ollama running | Immediate ack returned (<2s); summary, tags, and embedding vector saved in DB (`status='processed'`) | Fake summary saved or timeout |
| **T3** | Capture with Ollama Offline | Stop Ollama server; send text | Immediate ack returned, followed by error message; item marked `status='failed'` in DB | Dummy summary stored |
| **T4** | Semantic Search Hit | Save machine learning note; query `/search deep neural networks` | Relevant note returned with summary, tags, and score | Keyword fallback used |
| **T5** | Search with Ollama Offline | Stop Ollama server; run `/search test` | Direct error message returned: "embedding model unavailable" | Fake search or SQL LIKE fallback |
| **T6** | Resurface & Triage | Save item with artificially backdated `created_at`; run `/digest` | Returns item with `/keep` and `/archive` options | Fake/random item returned |
| **T7** | Archive Action | Run `/archive <id>` on an item | Item marked `is_archived = 1`; omitted from subsequent `/digest` queries | Item remains in active resurfacing |
| **T8** | Service Restart Resilience | Restart bot process | All existing items, embeddings, and media accessible in `slothbox.db` | Data corrupted or missing |
| **T9** | Empty Stash Handling | Run `/stats` and `/recent` on clean database | Displays "0 items in stash" | Hardcoded demo items appear |

## 10. Explicit Prohibitions

* ❌ **NO hardcoded demo/seed items** in source code or database migrations.
* ❌ **NO fallback placeholder summaries** (e.g., *"Summary unavailable"*) when Ollama fails.
* ❌ **NO keyword-based fallback** (`LIKE '%query%'`) when semantic embeddings fail.
* ❌ **NO Webhook or cloud server deployments** (strictly Long Polling).
* ❌ **NO cloud databases** (strictly local SQLite `slothbox.db`).
* ❌ **NO synchronous blocking Ollama calls** inside the Telegram async event loop.
* ❌ **NO open public access** without Telegram User ID authorization verification.
